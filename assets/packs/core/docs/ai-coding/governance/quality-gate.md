# AI Coding 质量门禁

只有全部适用的阻断检查通过后，变更才算完成。

## 需求

- 验收标准明确且已覆盖。
- 未将待人工决策事项隐藏为假设。
- 无关行为和兼容性得到保留。

## 设计与代码

- 职责内聚，依赖方向有效。
- 复用现有能力，不重复实现业务规则。
- 正确处理状态、错误、空值、资源、并发和生命周期。
- 保护敏感数据，并校验外部输入。
- 新增抽象理由充分且可测试。

## 代码坏味道检查

### 通用

- 无上帝类、过长方法、过深分支、散弹式修改或职责泄漏。
- 无重复业务规则、复制粘贴分支、基本类型偏执或用布尔参数隐藏多种行为。
- 无仅转发调用的无价值外壳、伪 Factory、循环依赖或反向依赖。
- 无可变全局状态、隐式时序耦合、吞异常、空 `catch`、不对称资源释放或敏感日志。
- 新抽象确实收敛变体或隔离依赖，不以未来可能性为由过度设计。

### Android

- Activity、Fragment、View 和 Adapter 不承载网络、数据库、同步或领域编排。
- 无主线程网络、磁盘、重量级数据库或大图处理。
- 异步任务、观察者、回调、Receiver 和资源遵守生命周期并成对释放。
- UI 状态保持单一真源，不同时由 DataBinding、观察回调和手工 `setText` 等多通道驱动。
- 不持有失效的 Context/View，不向 Intent 或 Bundle 塞入大对象，不绕过既有导航、服务或数据门面。

### 医疗、设备与同步

- 不臆造医疗阈值、参考范围、危急值、质控规则或临床解释。
- 不混淆患者、样本、医嘱、测量和设备身份，不以显示字段代替稳定业务键。
- 不绕过既有设备协议入口，不吞掉帧校验、超时、重试、断连或设备状态错误。
- 不在日志、崩溃信息或测试夹具中暴露密码、令牌、密钥、完整患者标识、病历号或完整测量载荷。
- 同步方向、幂等、冲突解决、删除语义、时间来源和落库边界均来自已批准设计；不以最后写入获胜等默认策略补齐缺失规则。
- 线数据、领域对象和持久化实体职责分离；映射、事务、迁移、回滚和离线行为有明确归属。

发现坏味道时，应判断其是否由本次变更新增或放大；阻断风险必须修复，无关存量问题记录但不扩大本次范围。

## 验证

- 已处理正常、边界、失败和回归场景。
- 已实际运行相关静态检查、测试和构建。
- 人工、设备、集成和人工评审事项保持明确。
- 最终报告不声称未执行的证据已通过。

任何适用检查失败都会阻断交付。人工评审项可以保持待办，但不得将变更表述为已完成全部验证。
