# AI Coding 宪章

## 目的

AI 辅助工程工作，但不负责定义需求、架构、领域规则、验证结论或发布决策。开发者始终对提交的变更负责。

## 变更纪律

- 采用最小安全变更。
- 保留与需求无关的行为。
- 创建新抽象前，先检查现有职责归属。
- 未经明确批准，不得增加依赖、替换架构、改变公共 API 或调整持久化。
- 不得臆造领域阈值、协议语义、冲突规则或安全行为。

## 规格与执行

非平凡变更遵循：

```text
需求 → 规格 → 分析 → 计划 → 设计
→ 必要时人工批准 → 实现
→ 评审 → 验证 → 交付
```

OpenSpec 是需求与变更产物的首选事实源；项目规则是实现约束的权威来源。

## 质量

生成的代码必须可维护、内聚、可测试、安全，并符合项目架构。仅编译通过不能证明工作完成。

## 可追溯性

有实质影响的变更应保留：
- 目标、非目标和验收标准
- 影响与风险
- 设计决策与任务
- 评审发现
- 已执行验证与待完成人工检查
