# AI Coding 治理流程

## 权威顺序

发生指令冲突时，按以下优先级处理：

1. 用户明确提出的需求和已批准的验收标准
2. 项目专属规则与架构
3. 稳定规格与当前 OpenSpec 变更
4. `docs/ai-coding/governance/constitution.md` 与 `docs/ai-coding/governance/decision-boundaries.md`
5. 本可移植流程

不得臆造业务、医疗、协议、同步、安全、数据结构或公共 API 语义。

## 变更记录

非平凡变更应在条件允许时使用 OpenSpec 变更目录：

```text
openspec/changes/<change-name>/
  proposal.md
  specs/<capability>/spec.md
  design.md
  tasks.md
```

OpenSpec 是需求与变更产物的事实源；AI Coding 负责执行纪律与证据。不要创建 `openspec/changes/active/`；当前 OpenSpec CLI 会将 `active` 识别为变更名。

无法使用 OpenSpec 时，应在对话或项目事项中维护同等信息：目标、非目标、验收标准、设计、任务、风险和验证。

## 状态机

```text
ANALYZE → PLAN → DESIGN → APPROVE → IMPLEMENT
   → REVIEW → TEST → [FIX → REVIEW → TEST]
   → 可选 REFACTOR → DELIVER
```

涉及架构变更、公共 API、持久化、安全、医疗逻辑、设备行为、同步语义或项目定义的其他边界时，不得跳过 APPROVE（人工批准）。

## 1. Analyze（分析）

读取需求、项目规则、架构、相关规格、当前变更和现有实现。

产出：
- 目标、非目标和验收标准
- 现有职责归属与可复用能力
- 受影响模块、调用方、数据、API、并发、生命周期和兼容性
- 正常、边界、失败和回归场景
- 风险等级与未决事项

分析阶段不得修改实现文件。

## 2. Plan（计划）

形成边界清晰的任务序列。每项任务必须明确：
- 文件或职责范围
- 行为变化
- 复用决策
- 验证证据
- 对前序任务的依赖

优先采用最小安全变更，并将必需工作与可选清理分开。

## 3. Design（设计）

设计深度应与风险相匹配。

对于每个新增类、接口、模式或层次，说明：
- 单一职责
- 现有职责归属为何不足
- 依赖及其方向
- 已考虑的更简单方案
- 可测试接缝

适用时应包含数据流、错误流、线程与生命周期约束、兼容性、回滚方案和迁移影响。跨越决策边界时必须获得人工批准。

## 4. Implement（实现）

写入前：
- 确认已批准任务和当前工作树状态
- 搜索已有等价实现
- 加载适用的项目规则

实现期间：
- 保持 diff 范围受控且内聚
- 保留无关行为
- 优先组合和显式状态
- 有意识地处理错误与资源
- 不得隐式增加依赖或改变架构
- 确定性行为发生变化时同步更新测试

每次完成一项可独立评审的任务。

## 5. Review（评审）

评审实际 diff，而不是预期意图。按以下级别分类问题：
- 阻断：正确性、数据丢失、安全、契约或回归风险
- 重要：可维护性、可测试性、生命周期、并发或架构问题
- 可选：不影响发布风险的完善项

依据 `docs/ai-coding/governance/quality-gate.md` 执行完整质量门禁和代码坏味道检查，覆盖需求、重复、单一职责、封装、依赖方向、空值与错误行为、敏感数据、兼容性和测试。避免提出与本次变更无关的风格问题。

## 6. Test（测试）

根据验收标准和影响分析设计测试：
- 正常行为
- 边界以及空值状态
- 依赖与 IO 失败
- 适用时的生命周期与并发
- 对保留行为的回归验证

先运行范围最小且有效的检查，再按风险执行更广泛的构建或集成检查。命令未成功完成时，不得声称检查已通过。

## 7. Fix（修复）

对于每个已确认缺陷：
1. 识别根因和证据
2. 定义最小安全修正
3. 可行时新增或更新回归测试
4. 实施修复
5. 重复评审与测试

不得将修复扩大为宽泛重构。

## 8. Refactor（重构）

仅在行为保持、范围明确且可验证的前提下重构。说明坏味道、目标设计、迁移步骤和回滚方式。不得将无关清理混入功能或修复。

## 9. Deliver（交付）

报告：
- 结果与验收标准覆盖情况
- 按职责归类的新增、修改和删除文件
- 重要设计与兼容性决策
- 实际执行的命令及结果
- 未解决风险、人工/设备/集成检查及人工评审门禁
- OpenSpec/任务状态和后续工作

完成必须具备实现证据以及适用的评审和验证；仅编译通过不足以证明完成。
