# flow-glucose-measurement（测量细序）

## 前置门禁

1. 由 `/flow-glucose-domain` 确认当前 AI Coding 阶段。
2. 写入前加载目标项目规则、已批准规格与医疗治理边界。
3. 医疗阈值、参考范围、危急值、QC、身份、协议和同步语义缺失时停止推断。

## 按职责搜索

实现前在目标项目搜索并确认：

- 页面状态的唯一所有者（Model、ViewModel 或等价状态容器）
- 试纸与设备状态入口
- 公共设备通信或协议门面
- 解析与结果对象创建职责
- 结果样式、标志、单位、精度与项目类型入口

若存在 `docs/ai-coding/bindings/*-glucose.md`，将其中类名作为搜索索引；类名不是复制实现或绕过项目规则的依据。

## 实现细序

1. 从页面入口追踪到共享状态所有者，不在 View 层建立第二份业务状态。
2. 展示优先使用项目既有数据绑定或声明式状态通道；避免观察后再手工驱动同一属性。
3. 复用已有试纸状态机、设备通信入口、解析器与结果工厂，不复制协议分支。
4. 复用既有结果样式、单位和精度入口，不硬编码医疗阈值或设备语义。
5. 同族项目可共享测量骨架，但不得把某一项目的阈值、量程、单位或协议推断到其他项目。
6. QC 属于相邻领域，应切换到目标项目的 QC 真源。

## 写后检查

- 检查是否新增第二状态通道、View 层业务编排或生命周期泄漏。
- 检查是否绕过设备门面、复制协议/样式分支、硬编码单位精度或医疗阈值。
- 执行 `/ai-review` 与按风险设计的 `/ai-test`；设备行为保留人工与实机验证。
